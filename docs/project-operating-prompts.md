# 销售 Agent 项目执行提示词

这些提示词用于后续 Codex 会话。它们是执行模板，不替代产品主计划、需求规格或用户确认。
当前唯一用户-facing 主线是“销售跟进 Agent：持续执行闭环”；主动任务跟进、商机推进和
提醒是该主线的内部能力切片，不应被拆成相互竞争的产品。
使用前先读取 `docs/project-master-plan.md`、`docs/specs/05-requirements-traceability.md`、
`docs/current-state.md` 以及与当前切片相关的 SDD/TDD。

## 1. 项目复查与规划提示词

```text
你正在维护“销售跟进执行 Agent”。先读取 docs/project-master-plan.md、
docs/specs/05-requirements-traceability.md、docs/current-state.md 和当前切片相关规格。

目标：用代码、测试、规格、数据库迁移和真实飞书/Web 证据核对当前完成度，形成可执行的下一步，
不要凭历史记录或文件名推断完成。

要求：
1. 先列出证据矩阵，区分 UI Verified、Automated Green / UI pending、Partial、Draft。
2. 核对产品总纲中 P1 持续执行闭环及其内部能力依赖，优先找出阻塞当前最高优先级切片的缺口。
3. 只提出一个最高价值的下一切片，说明目标、范围、需求编号、验收门禁和停止条件。
4. 发现代码、规格和历史记录冲突时，保留冲突证据，不自行抹平。
5. 未经明确授权，不改代码、不写数据库、不操作真实飞书、不发布。

输出：现状结论、证据矩阵、最高优先级切片、风险、需要用户确认的决策。
```

## 2. P1-CTX 上下文读取与执行闭环提示词

```text
按销售 Agent P1-CTX 目标推进一个最小可验证切片：让跟进流程在生成草稿前读取客户、商机、近期
跟进和任务上下文，并在人工确认后按版本执行。

先检查现有端口、shared/api.interface.ts、server/database/schema.ts、相关 SDD/TDD 和测试。
不要把 Base 的列名泄漏到 Agent 推理层，不把 Mem0 当客户或商机事实源。
文本输入可以先做不持久化的实体预识别，再读取本人范围的上下文并生成最终草稿；机器人和 Web
草案都必须复用同一只读端口，多客户/多商机匹配必须暂停自动选择，卡片和 Web 草案展示可核验的来源引用。

实现边界：
- 先写 Red，再做最小 Green；
- 必须覆盖无匹配、多匹配、权限不足、跨租户、旧信息冲突、重复消息和重复确认；
- 写入仍遵守“预览 -> 人工确认 -> 跟进先于任务”的顺序；
- 高风险字段和外部通知不得自动执行；
- 保持 LangGraph 为唯一生产对话编排，不恢复旧运行时双写。

验证：运行受影响测试、Agent 全量回归、Postgres 集成、三套 TypeScript、ESLint、Agent/Web
构建和 git diff --check。最后说明真实飞书/Web 哪些已验收、哪些仍待验收。
```

## 3. P1 内部主动任务跟进提示词

```text
在 P1-CTX 和 P1 的确认执行闭环稳定后，只实现一个内部主动触发器，默认选择“商机超过 7 天没有更新”。

先读取项目主计划、任务/商机数据模型、权限规则和现有飞书消息/任务端口。定义触发条件、
扫描范围、租户时区、去重键、免打扰、解释原因、建议动作、确认门、升级主管和失败恢复。

约束：
- Agent 可以判断是否提醒和提出建议，但不能未经确认修改商机阶段、金额、预计成交时间或对外发消息；
- 定时器/事件系统负责触发，模型不负责伪造触发；
- 重复扫描必须幂等，跨租户不可见，失败必须可审计和重试；
- 先完成一个触发器的自动化和真实 UI 闭环，再扩展逾期任务或承诺未兑现。

输出并验证：触发契约、状态机、Red/Green 测试、运行日志、真实 UI 验收步骤和未完成风险。
```

## 4. 真实 UI 回归与证据对账提示词

```text
对当前 LangGraph 构建执行一次真实飞书/Web 回归，不要修改业务逻辑来掩盖环境问题。

按最新追踪矩阵选择尚未 UI Verified 的场景，至少包括：普通问答、客户事实澄清、自然语言
“帮我写跟进”、执行中状态、唯一成功/失败终态和结果修订。

每条场景都记录：测试标记、输入消息、时间和租户、可见 UI、Agent 日志、Checkpoint、控制库、
Base、Task、审计事件和是否产生副作用。失败时先判断是回调/隧道、权限、数据状态、模型、
卡片呈现还是业务代码问题；不得把自动化测试结果当作 UI 证据。

完成后只更新 docs/current-state.md 和 docs/specs/05-requirements-traceability.md 的证据，
明确通过、失败、待重试和阻塞输入。未经用户另行授权，不发送非验收消息，不修改业务数据。
```

## 5. 文档同步提示词

```text
完成一个切片后，同步销售 Agent 文档：
1. 更新需求追踪矩阵的状态、自动化证据、UI 证据和日期；
2. 在 current-state.md 追加事实日志，保留历史记录；
3. 如有不可逆取舍，新增或更新 decisions 文档；
4. 若改变阶段依赖，更新 project-master-plan.md；
5. 检查所有相对链接、需求编号、状态名称和命令一致；
6. 运行 git diff --check，并报告未完成项。

不要用“已实现”代替“自动化通过待 UI”，不要删除旧 Red 证据，不要把推测写成事实。
```
