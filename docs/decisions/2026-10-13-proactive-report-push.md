# 日报与主管周报灰度启用决策问答

日期：2026-10-13

## 问：日报什么时候发送？

答：按租户业务时区，周一至周五每天 17:00 发送。周六、周日不发送；这里的工作日暂按星期
定义，不接法定节假日与调休日历。该规则由 D-061 覆盖 D-060 的“包括周末”。

## 问：当天没有跟进、商机变化或任务时还发吗？

答：发。发送简短“今日无新增”日报，让用户明确知道系统完成了当天汇总，而不是误以为调度
失效。

## 问：主管周报发给谁、什么时候发？

答：当前灰度只发给产品负责人本人。该账号在 Demo 租户中保留销售角色并追加主管角色，团队
周报每周五 17:05 发送，与 17:00 日报错峰。

## 问：还发送个人周报吗？

答：本轮不发送。主管只收每日个人日报和每周团队周报，避免同一人在周五收到内容高度重复的
个人周报与团队周报。

## 问：任务提醒和商机风险提醒会一起开启吗？

答：不会。本轮持久配置只允许 `daily_report` 和 `weekly_team`，其他主动通知继续关闭，后续按
独立验收逐类开放。

## 问：如何防止误发给其他人？

答：发送前同时校验通知类型、租户、成员和飞书 open_id。任一项不一致就停止，不读取该成员的
业务数据、不创建投递账本，也不调用飞书发送接口。

## 问：为什么不把账号直接写进代码或数据库迁移？

答：账号是当前 Demo 环境配置，不是所有企业共用的产品规则。通用代码保留多租户能力，真实
标识只放在 Git 忽略的本地配置中；主管角色通过查询后幂等追加。

## 问：如何证明自动推送真的可用？

答：先固定时间运行 plan-only，再真实发送一张本人团队周报，回读飞书消息与持久账本，并重复
运行验证不会再次发送。全部通过后才安装每 5 分钟触发一次的持久调度。

## 问：如何验证周报定时推送，而不永久修改正式时间？

答：保留正式周五 17:05 规则，只创建一次性本机测试任务，在未来几分钟用受控测试时钟命中
周报窗口。测试只允许当前 tenant/member/open_id，完成后核对飞书卡片、发送账本和重复去重，
再删除一次性任务。
