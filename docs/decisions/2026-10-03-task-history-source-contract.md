# 任务历史来源契约

日期：2026-10-03  
状态：`Confirmed / receipt ingestion implemented / coverage proof pending`

## 背景

任务履约 Agent 当前拥有本人任务的读取能力和 Agent 观察事件账本，但这不等于飞书任务的
全量历史。为避免后续接入订阅后把“收到过事件”解释为“没有漏事件”，先固定来源语义和
`coverage.taskHistory` 的升级条件。

## 已核对的来源语义

| 来源 | 能提供什么 | 不能证明什么 |
| --- | --- | --- |
| `listRelatedTask` | 当前授权范围内与本人相关的任务列表，可分页、筛选 | 不能回溯历史；列表缺失不能证明任务未完成 |
| `task.task.update_user_access_v2` | 订阅后可见任务变更的前向回执；当前实现记录最小元数据和 SHA-256 哈希 | 不能补发订阅前历史，不能证明事件连续性；也不提供最终任务状态或销售归属 |

## 接入要求

1. 当前实现只接收并记录最小回执元数据：以 `(tenantId, eventId)` 去重，保存任务 GUID、事件类型、
   发生/接收时间、回执状态和最小元数据的 SHA-256 哈希；不保存原始事件体或任务正文。
2. 回执接收层不二次读取任务、不更新快照或履约事件账本、不发送提醒，也不从事件内容推断销售身份。
3. 后续若要主张覆盖窗口，必须保存租户、订阅配置、订阅建立时间和可用的起始游标/版本，并记录
   断线、鉴权失败、订阅变更和消费错误。
4. 后续状态处理只能触发按精确任务 GUID 的二次读取；不得根据标题、时间相近或列表缺失关联任务。
5. 恢复后必须执行受边界约束的补偿读取，无法覆盖的窗口显式标为 `partial` 或 `unavailable`。
6. 只有能够证明查询边界、事件去重、消费连续性、二次读取成功率和未覆盖窗口为空时，才允许
   `TaskGateway.readTaskHistory` 返回 `coverage=full`；任何警告均 fail closed。

## 当前结论

`task.task.update_user_access_v2` 回执接收器已实施，但它只证明系统收到过某条可见事件，不能证明
完整任务历史或无遗漏。当前 `FeishuTaskGateway` 仍未提供可信历史来源，因此
`coverage.taskHistory=full` 继续禁用。产品可以展示当前任务快照和 Agent 自己观察到的证据，但不能
计算全量完成率，也不能因列表中没有任务就判断历史承诺未兑现。
