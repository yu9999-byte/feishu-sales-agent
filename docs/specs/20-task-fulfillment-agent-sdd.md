## 1. 产品目标

帮助销售快速知道本人未完成任务中哪些已经逾期、今天到期、即将到期或缺少期限，并核对
最近 180 天通过 Agent 确认的跟进承诺是否有任务承接。v1 是只读检查，不自动催办、
不修改任务、不通知主管，也不以任务不可见推断承诺已兑现。

## 2. 触发与入口

- 用户从 Web 导航进入 `/tasks`，或手动刷新页面。
- 服务端通过 `GET /api/platform/task-fulfillment` 生成当前快照。
- 可选 `date=YYYY-MM-DD` 用于确定性测试或受控复盘；默认使用租户时区的当天日期。
- v1 没有定时调度、事件订阅或机器人主动推送。

## 3. 身份、权限与数据范围

- 必须存在有效飞书 Web 会话。
- 服务端重新校验租户、成员状态和 `task:read` 权限，不信任前端导航。
- 仅使用会话成员的 `feishuOpenId` 查询本人负责的未完成任务；对承诺中已有的精确
  `taskGuid`，在任务列表未命中且列表完整时额外读取任务详情，以确认完成或读取失败。
- 另按同一销售负责人读取飞书已完成任务，使用 `is_completed=true` 分页检索，最多读取
  10 页；只有存在有效 `completed_at`（ISO、秒级或毫秒级且大于 0）的记录才计入已完成任务
  明细和指标。该结果代表当前 API 检索范围，不代表全部历史完成记录。
- 按同一租户和销售身份读取最近 180 天成功执行的 Agent 动作，最多 500 条；到达上限时
  标记结果可能不完整。其他渠道创建的跟进承诺不在本次范围内。
- 外部任务来源异常时返回 `unavailable`，已完成任务分页或检索范围不完整时返回 `partial`
  和可见警告；正常完成任务检索标记为 `search_scope`。
- 每次观察保存租户/销售/任务 GUID 的最新状态快照；标题、期限、状态或完成时间发生变化时返回
  变化证据。首次观察只建立基线，不伪造变化。
- 控制库同时保存 Agent 观察到的任务状态事件（`observed`、`changed`、`completed`、
  `reopened`），按租户、销售和精确任务 GUID 隔离读取。这是 Agent 自己观察到的证据账本，
  不是飞书全量历史事件流，也不能证明观察窗口之外没有变化。

## 4. 确定性判断

任务截止时间先转换为租户时区的本地日期，再与检查日期比较：

| 类别 | 规则 | 优先级 | 建议 |
| --- | --- | --- | --- |
| 已逾期 | 截止日期早于检查日期 | Critical | 确认是否继续执行并重新承诺时间 |
| 今日到期 | 截止日期等于检查日期 | High | 当天完成或在截止前更新安排 |
| 即将到期 | 未来 1 至 3 天 | Medium | 提前准备材料和协作 |
| 未设期限 | 没有有效截止时间 | Medium | 补充可检查的截止时间 |
| 正常排期 | 未来超过 3 天 | Normal | 按计划推进并及时更新变化 |

排序顺序固定为：已逾期、今日到期、即将到期、未设期限、正常排期；同类有截止时间的任务
按时间升序排列。模型不参与日期分类，不得改变确定性规则。

承诺仅采用最终选中的任务候选和执行结果中的 `taskGuid` 精确关联，不按标题猜测。无 GUID
表示未关联任务；列表完整时对未命中的 GUID 读取详情。完成证据以可解析且大于 0 的
`completed_at` 为准，兼容 ISO、秒级和毫秒级时间；`"0"`、空值、非法值或与它们冲突的
原始完成状态不得标记“已完成”。

任务历史恢复只能使用精确 GUID 的明确事件：最新事件为 `completed` 时可恢复“已完成”，
最新事件为 `reopened` 时可恢复“已重新开放”；只有 `observed` 或普通 `changed` 时仍须
核实。事件读取失败、事件来源不完整或超出查询范围时不得做完成结论。跨任务只有在外部来源
明确提供 `relatedTaskGuid` 且关系为 `replaces` 时才允许建立替代关系；当前快照观察不会自动
按标题、时间相近或列表缺失生成跨任务关系。
详情读取失败标记“详情暂不可用”，详情为空标记“当前不可见”。对精确关联且当前可见的非完成
任务，若状态为 `in_progress`、`doing`、`processing`、`started` 或对应中文值，额外标记“部分完成”；
其他可见非完成状态标记“仍未完成”。任务来源不完整时标记“任务读取不完整”，不做缺席判断，
详情/列表读取失败时标记“待核实”。

## 5. 响应与页面

接口返回检查日期、租户时区、生成时间、状态、分类指标、任务明细、建议、数据覆盖范围和警告。
页面展示：

- 未完成、逾期、今日到期、三天内到期、未设期限计数；
- 当前已完成任务检索范围内的已完成任务计数、完成时间和飞书任务链接；
- 按优先级排列的建议处理顺序；
- 每条任务的分类、截止时间、建议和飞书任务链接；
- Agent 已确认承诺的关联未完成、逾期、未关联和不可核实统计、明细与来源链接；
- Agent 已确认承诺的确定性履约判断：已完成、部分完成、仍未完成或待核实；
- 已完成、重新开放和标题/期限/状态变化的任务证据及最近一次快照范围；
- 飞书任务完成时间，以及完成/重新开放变化前后的完成时间证据；
- 明确的数据边界，避免把未读取的完成历史解释成“没有完成任务”。

## 6. v1 明确不做

- 不承诺读取完整的已完成任务历史；当前只展示负责人过滤、最多 10 页检索范围内且有有效
  完成时间的记录，不能据此计算全量完成率。
- 不把 Agent 事件账本当成飞书全量历史；事件仅覆盖本 Agent 实际观察到的精确任务 GUID。
- 不按标题相似、时间接近、列表缺失或普通状态变化把一个任务关联为另一个任务；没有显式
  `relatedTaskGuid + relation: replaces` 时，不恢复跨任务兑现判断。
- 不判断没有精确任务证据的本次跟进是否完成、部分完成或变更了既有承诺；当前只对精确关联
  任务的状态做只读确定性判断。
- 不写任务状态、标题、截止时间或负责人。
- 不发送本人提醒、群消息、短信、电话或主管升级。
- 不把任务结果写入 Base，不产生新的业务记录。

## 7. 失败与停止条件

- 会话无效返回 401，权限不足返回 403，租户集成不可用返回 503。
- 日期或时区无效时返回 `unavailable`，不使用服务器默认时区猜测。
- Task API 失败时零推断、零副作用；分页不完整时保留已读取结果但标记 `partial`，
  未匹配 GUID 仅标记不可核实。承诺历史读取失败或达到上限也标记不完整。

## 8. 后续演进

下一阶段需要接入可信的全量任务历史/事件来源，并在有明确替代关系时补齐跨任务完成证据，
再判断没有精确任务承接的承诺是否兑现。主动提醒必须复用租户策略、免打扰、持久去重账本、
最新状态重读和结果未知人工对账；更新任务、通知主管或对外沟通仍需权限与人工确认。

## 9. 验收标准

- 五类任务在租户时区下分类正确且风险顺序稳定。
- 空数据不虚构已完成任务；来源异常和分页不完整状态可见。
- 精确 GUID、最终候选、租户/本人隔离、无任务和不可见任务均有正反测试。
- 首次快照、任务变更、完成和重新开放证据均有自动化测试；详情读取失败必须保守降级。
- 事件账本按租户/销售/GUID 隔离，覆盖首次观察、普通变化、完成、重新开放和精确历史读取；
  事件读取失败必须降级为待核实，不能把观察账本解释为全量历史。
- 有效 ISO/秒/毫秒完成时间和 `completed_at="0"` 有正反测试；零时间即使伴随
  冲突状态也不得标记完成。
- 精确关联任务的已完成、部分完成、仍未完成和待核实状态均有自动化测试；进行中状态只能
  作为建议性履约判断，不能直接写回任务或跟进。
- API 和页面均受服务端 `task:read` 权限保护。
- 自动化测试、三套 TypeScript、Lint、Stylelint、Agent/Web 构建和全量回归通过。
- 真实销售登录态核对内容、链接和窄屏视觉后，才可升级为 `UI Verified`。
