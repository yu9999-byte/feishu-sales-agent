# 产品需求规格

状态：`Approved / 2026-09-20；对话与质检决策增量`

## 1. 产品定义

销策 Agent 是运行于飞书工作场景、面向多企业 SaaS 的销售工作与决策助手。它不只保存一条
跟进，而是把销售过程连接成持续闭环：

```text
意图理解与对话
-> 按需多模态采集
-> AI 生成可用跟进
-> 保存前可用性检查
-> 人工确认
-> 客户/商机/任务沉淀
-> 条件性项目推进诊断
-> 分角色提醒和建议
-> 团队 Review
-> 最佳实践回流
```

一线销售优先在飞书机器人、卡片和飞书原生资源中完成高频操作；复杂浏览、分析和配置在从
飞书打开的 Web 应用中完成。

## 2. 产品角色

| 角色 | 主要目标 |
| --- | --- |
| 一线销售 | 少录入、不错漏、知道下一步、方便复盘客户 |
| 销售主管 | 及时发现风险项目和需要辅导的人，不依赖人工周报 |
| 销售高管 | 看清目标差距、预测变化及影响达成的关键商机 |
| 租户管理员 | 配置组织、权限、数据源、规则、知识库和 Playbook |

## 3. 产品原则

1. **证据优先**：事实、评分和建议必须能回到销售原话、会议内容或业务记录。
2. **人工确认写操作**：AI 草案、任务、阶段变更和对外推送在对应权限主体确认后执行。
3. **减少管理噪音**：普通跟进只反馈本人；风险、里程碑或明确协作请求才触发主管/协作者。
4. **租户与数据范围先于模型**：任何检索和工具调用先计算租户、角色和数据范围。
5. **事实与判断分离**：原始内容和业务事实不可被生成文本覆盖；AI 判断单独存储并带版本。
6. **飞书优先但不锁死**：首个数据源使用 Base，业务逻辑通过端口适配未来 CRM。
7. **先理解意图再行动**：普通问答不进跟进工作流；只有明确记录指令或正在补充本次跟进时
   才生成跟进。未知业务事实与未接通查询必须明说，不能由模型编造。
8. **过程可感知、动作可恢复、结果可编辑**：外部写入必须展示执行态；失败可编辑或幂等重试；
   成功结果可修订原记录，不用重复创建覆盖错误。

## 4. 核心业务闭环

### 4.1 跟进采集与生成

销售可以从卡片表单、机器人文本/语音、飞书妙记或会议纪要、飞书文档发起跟进。系统解析
原始内容，生成可编辑的标准跟进，区分客户事实、需求、异议、共识、风险、商机变化和下一步。

### 4.2 质量与推进质检

系统在保存前输出可用状态、阻断项与建议补充；内部质量快照保留供规则回归。保存后结合历史记录
判断跟进频率、阶段停留、客户情绪、竞品介入和任务履约。分数是可解释建议，不能作为惩罚性
绩效结论的唯一依据，默认确认卡不展示数字分与 A/B/C/D 等级。保存前的记录可用性和保存后的项目健康度是不同判断；机器人来源的
编辑、再质检和确认均回到原飞书聊天，不强制跳 Web。

### 4.3 执行与推送

销售在同一张草案卡预览跟进与本人任务，**一次确认**后写入业务事实源，再自动创建已批准
的飞书任务。普通结果只回给销售；高风险、关键里程碑、
需要跨角色支持和逾期高优先任务按租户策略推送主管或协作者。
确认是整张表单的一次提交，不逐字段确认。确认后同一卡立即显示“执行中，请等待”，完成后
更新为成功或失败；成功和失败终态都提供恢复入口。

### 4.4 客户与商机决策

客户 360 和商机详情聚合联系人、历史跟进、文档、任务、阶段变化和 AI 洞察。拜访前生成
带证据的攻略；拜访后对比目标与结果，更新项目健康度并给出下一步建议。

### 4.5 团队 Review 与组织学习

日报、周报和 Weekly Review 使用已确认数据生成。管理者可下钻到证据。赢单和丢单达到足够
样本后才形成最佳实践候选，必须经管理员审核后进入已发布 Playbook。

## 5. 功能需求

### 5.1 平台与安全

- `PLT-001` 所有数据、缓存、任务、向量、报告和审计记录都必须带 `tenantId`。
- `PLT-002` 同一飞书用户在不同租户中的成员身份、角色和数据范围独立计算。
- `PLT-003` 支持销售、主管、高管、管理员四类基础角色及自定义汇报关系。
- `PLT-004` 所有查询、LLM 检索和工具调用执行资源级数据范围检查。
- `PLT-005` 所有写操作、AI 判断、推送和 Playbook 发布留下不可变审计事件。
- `PLT-006` 权限拒绝不得泄露目标资源是否存在或其他租户的标识。

### 5.2 多模态采集

- `ING-001` 卡片表单支持客户、联系人、沟通方式/时间/主题、正文及下一步等字段。
- `ING-002` 机器人文本输入继续支持多轮补充和上下文合并。
- `ING-003` 飞书语音消息转写后进入同一解析管线，并保留音频消息引用。
- `ING-004` 已授权的飞书妙记/会议纪要可被选择或粘贴链接导入。
- `ING-005` 已授权的飞书文档可被选择或粘贴链接导入；首版不支持任意公网文件抓取。
- `ING-006` 每次采集形成可追踪的输入作业，显示处理中、待补充、待确认、成功或失败。
- `ING-007` 来源无法读取、内容为空、转写失败或超长时给出可恢复错误，不能创建半成品记录。

### 5.3 跟进生成和质检

- `FUP-001` 从来源中提取客户、联系人、需求、异议、共识、金额、阶段、风险和下一步。
- `FUP-002` AI 生成一段可直接用于 CRM 的专业跟进正文，同时保留逐字段结构化结果。
- `FUP-003` 每个事实字段保存来源证据；没有证据的推断必须显式标记为建议。
- `FUP-004` 保存前可用性检查区分阻断项和建议补充：客户、有效正文和事实证据是写入门槛；下一步时间/方式/参与人是创建对应任务的门槛；联系人、沟通方式、需求、预算、决策链等本次未知项给可行动提示，不默认为销售失误。显式“暂无下一步＋原因”可保存但不建任务，不能由 AI 补造事实或任务。
- `FUP-005` 用户默认看到“可以保存/需要确认/建议补充”和具体原因；旧 0-100 质量快照与分项可为兼容和后台规则回归保留，不在日常确认卡突出数字与等级。项目诊断和按需销售辅导使用各自证据与触发条件。
- `FUP-006` 机器人输入在原聊天卡内编辑补充、检查修改并更新同一张卡；Web 可选但不作为确认门。最终确认版本作为唯一写入版本，确认卡同时预览本人待办候选。
- `FUP-007` 确认后匹配或创建客户/商机，保存跟进原文、生成文和质检快照。
- `FUP-008` 普通结果仅通知本人；高风险、关键里程碑和支持请求仅基于已确认事实、证据、租户策略、收件人权限与去重推送。跨团队支持对象和团队群里程碑须经销售明确确认。
- `FUP-009` 重复输入、重复确认和失败重试不得产生重复业务副作用。
- `FUP-010` 整表确认通过后，回调必须立即返回不可重复操作的执行中卡；外部写入只能在回调
  返回后启动，最终在同一卡显示成功、失败或部分失败。
- `FUP-011` 成功结果允许从同一卡发起预填修订；修订更新原 Base 跟进及已选择的原飞书任务，
  不创建重复跟进或重复任务。失败结果保留输入和进度，支持返回编辑或重试未完成步骤。

### 5.4 任务生命周期

- `TSK-001` 从下一步提取任务描述、截止时间、执行人和关联客户/商机；保存前可先抽取供同卡预览，保存成功后才创建已批准任务，无可执行下一步不创建。
- `TSK-002` 本人待办随最终跟进版本在同一张卡一次确认；按钮文案明确包含创建所示待办。涉及他人任务须再核验分配权限并明确确认；多任务集中预览与选择。
- `TSK-003` 回收飞书任务状态并维护待办、进行中、完成、逾期和变更状态。
- `TSK-004` 到期前一天、到期当天和逾期提醒遵循租户策略与免打扰配置。
- `TSK-005` 新跟进可提出任务已完成/部分完成/已变更判断并附证据；销售确认前不得自动更新飞书任务状态。
- `TSK-006` 高优先级逾期可通知主管，但同一规则在一个提醒周期内只能发送一次。

### 5.5 客户与商机

- `COP-001` 客户 360 展示基础信息、联系人、跟进时间线、商机、任务、文档和 AI 洞察。
- `COP-002` 商机详情展示阶段、金额、预计成交日、需求、决策链、竞争信息和推进时间线。
- `COP-003` 拜访攻略包含背景、需求、决策链、目标、话术、案例、风险和材料建议。
- `COP-004` 项目质检覆盖跟进频率、阶段停留、信息完整度、情绪、竞品和任务履约。
- `COP-005` 输出健康度、风险、关键缺口和按优先级排列的下一步建议。
- `COP-006` 赢单概率与预计成交时间必须展示模型/规则版本、证据和置信提示，不得伪装为事实。
- `COP-007` 销售只能读本人范围；主管读本人及下属；高管与管理员按租户策略读全量。

### 5.6 Sia 智能销售助手

- `SIA-000` 机器人私聊先进行意图与上下文路由，区分普通聊天、销售方法问答、内容生成、
  业务查询、跟进记录、任务/商机操作、项目诊断和歧义澄清；没有明确记录意图不得默认抽取跟进。
- `SIA-000A` 一般聊天和销售方法问答自然回复且不产生外部副作用；生成内容先展示草稿，
  不发送客户或写业务系统。低置信度意图只做简短澄清。
- `SIA-000B` 业务查询与写操作必须从授权数据源和工具获得结果；未接通时说明能力边界，
  不捏造“已查询/已创建”；写操作按版本、权限和确认执行。
- `SIA-000C` 明确记录指令或当前聊天的跟进补充态才进入跟进提取；取消、换话题、超时、
  跨聊天不能误合并原文。
- `SIA-000D` 对话意图、回复与动作留最小化审计，消息去重和租户隔离沿用平台边界；
  不将原始客户内容或模型密钥写入通用日志。
- `SIA-001` 支持产品知识、客户、商机、任务、打法和文档查询意图。
- `SIA-002` 回答只使用当前用户有权访问的数据，每个关键结论提供可打开来源。
- `SIA-003` 没有可靠来源时明确说明不知道，不得用常识补造企业事实。
- `SIA-004` 支持当前会话内多轮追问，跨会话记忆必须可查看和删除。
- `SIA-005` 对话式写操作生成执行预览，经确认和权限检查后调用现有工具。
- `SIA-006` 知识入库保留文档权限快照；权限变化后索引访问必须及时失效。

### 5.7 Review 和经营分析

- `REV-001` 自动或手动生成个人日报，包含活动、变化、任务、明日重点和支持事项。
- `REV-002` 主管可生成团队日报/周报和 Weekly Review，并下钻到成员、商机及证据。
- `REV-003` 人员效能分为工作量与有效性，不使用不可解释的单一排名作为绩效结论。
- `REV-004` 经营看板展示目标、已完成、Commit、AI Commit、Gap、趋势和关键影响商机。
- `REV-005` 报告使用生成时的数据快照，展示统计区间、生成时间和数据完整性提示。
- `REV-006` 定时报告失败可重试且不重复推送；人工重新生成保留版本历史。

### 5.8 最佳实践与 Playbook

- `BPA-001` 赢单/丢单分析只在达到租户配置的最小样本量后生成候选规律。
- `BPA-002` 候选最佳实践附样本范围、证据、适用条件和已知局限。
- `BPA-003` Playbook 支持草稿、待审核、已发布、已归档和历史版本。
- `BPA-004` AI 只能提交编辑建议；管理员审核通过后才能发布。
- `BPA-005` 记录建议曝光、采纳、执行和结果，用于评估而不是自动证明因果。
- `BPA-006` 支持小范围灰度，但灰度对象、周期和退出条件必须显式配置。

### 5.9 Web 与运营

- `WEB-001` Web 应用必须根据角色隐藏无权入口，并由服务端再次执行权限校验。
- `WEB-002` 所有主要页面具备加载、空、错误、无权限和数据过期状态。
- `WEB-003` 飞书卡片中的详情按钮使用受控深链打开对应 Web 资源。
- `OPS-001` 正式环境提供固定 HTTPS、健康检查、结构化日志、告警、备份和恢复演练。
- `OPS-002` 模型、飞书和 Base 故障采用有限重试、熔断/降级和可见失败，不无限循环。

## 6. 明确边界

- 首个业务事实源是飞书 Base；不在本阶段同时实现 Salesforce、纷享销客等真实连接器。
- 不复制参考产品的名称、品牌、视觉素材、专有文案、内部提示词或未公开实现。
- AI 预测属于辅助决策，不自动改变成交承诺、绩效结论或客户对外沟通。
- 应用市场发布、计费、合同和商业化运营不是功能完成的前置条件。

## 7. 已确认的产品规则

以下规则已于 2026-09-19 随 SDD 基线确认，作为实现默认值：

1. 高风险包括客户明确负面、竞品进入、关键决策人反对、阶段严重停滞和高优先任务逾期。
2. 主管推送采用事件触发且去重，不把每条普通跟进同步给主管。
3. 旧质量分快照只作内部诊断/回归；默认确认卡不用数字/等级评判销售。辅导需要主动触发。
4. 会议首版读取飞书妙记/会议纪要，不实现机器人实时入会录音。
5. 文档首版仅读取当前用户和应用均有权限的飞书文档。
6. AI Commit、赢单概率和效能分析在数据不足时显示“样本不足”，不输出伪精确数值。
