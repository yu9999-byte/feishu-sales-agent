## 1. 渠道职责

| 渠道 | 承担的任务 | 不承担的任务 |
| --- | --- | --- |
| 飞书机器人私聊 | 自然聊天、意图澄清、销售问答、内容草稿、快速录入、提醒与结果 | 大型表格和复杂配置 |
| 飞书消息卡片 | 明确动作的原聊天表单、草案编辑、保存前可用性提示、任务预览、一次确认、结果与条件风险提示 | 每条问答固定发卡、多页分析和批量管理 |
| Web 应用 | 客户 360、商机、Review、看板、Playbook、管理配置 | 代替所有高频对话 |
| Base | 首个业务事实源和人工核验后台 | 面向终端用户的完整产品 UI |
| 飞书任务 | 执行下一步、提醒和完成状态 | 保存完整客户历史 |

## 4. 飞书交互

### 4.1 机器人首页卡片

包含“写跟进”“从妙记导入”“从文档导入”“查看今日任务”“问助手”五个入口，以及最多三条
需要本人处理的提醒。主管额外显示“团队风险”和“本周 Review”。

### 4.1.1 对话路由

收到文本先判聊天、销售方法问答、内容生成、业务查询、明确跟进、任务/商机操作、项目诊断
或歧义。纯问答以文本回应，不生成跟进卡；只陈述业务事实时先澄清“记录还是分析”。
明确记录且有内容才开始下方跟进卡片流程。当前切片未接通的业务查询/动作必须诚实降级，
不能把查询偷换成写入，也不能伪装已读取 Base。

### 4.2 跟进卡片流程（三种卡，条件发送）

```text
选择来源
-> 来源读取/转写
-> AI 生成
-> 原聊天：事实摘要＋保存前可用性检查＋待办候选预览卡
-> 在原卡片一次性编辑完整表单
-> 一次提交确认最终跟进版本及选中的本人待办
-> 同一卡立即显示“执行中，请等待”
-> 先写客户/商机/跟进，再自动创建已批准的飞书任务
-> 同一卡更新为成功/失败，提供查看、编辑或重试
-> 新的可行动项目风险/关键变化或主动请求：项目推进质检卡
```

第一张卡至少展示生成跟进正文、客户/商机、保存前阻断项和建议补充、风险证据、
下一步三要素、待办标题/本人负责人/截止时间/关联对象。表单只保留一个整表主提交按钮
“确认保存并创建所示待办”和“取消”；无任务时按钮明确为“确认保存（不创建待办）”。
销售提交补充后更新同一张卡，不得强制跳 Web；Web 仅是销售主动选择的复杂编辑入口。
旧评分可在后台诊断/版本记录中查看，默认确认卡不显示 0–100 数字或 A/B/C/D 等级。
确认前不写 Base 或 Task。任务候选变化后旧确认版本失效；多任务在一张卡内选择。

确认后不新增一张重复主卡：原卡立即进入执行中，并在结束后就地展示保存、任务创建和部分
失败的真实结果与链接。成功卡可打开预填整表修订；失败卡可返回编辑或重试。
第三张项目推进质检卡与保存前内容质量分不同，只有新风险、关键变化或销售主动要求时发；
报告、跨角色通知和到期提醒按各自事件独立触发，不能把普通跟进固定扩展为多张卡。

Web 表单中的完整度可随字段变化即时刷新并定位缺口；飞书卡片按提交或点击“检查”后刷新
同一张卡，不承诺按键级实时。客户、联系人、沟通方式、下一步都是检查项；未知联系人、
暂无下一步必须由销售显式说明原因，不能自动补造，缺客户或有效正文不能确认。

### 4.3 风险推送卡片

主管卡片只展示其有权访问且已确认的项目，包含触发原因、证据摘要、影响、销售当前建议和详情链接。
同一风险未发生等级或证据变化时不重复推送。

## 5. 通用页面状态

每个页面必须明确设计以下状态：

- `loading`：保留结构的骨架屏。
- `empty`：说明为何为空并给出下一步入口。
- `error`：可重试错误和不可重试错误分开表达。
- `forbidden`：不显示资源标题或敏感摘要。
- `stale`：标记数据更新时间并允许刷新。
- `partial`：外部数据源部分失败时标出缺失范围，不能伪装完整。

## 6. 响应式与可访问性

- 桌面端优先支持主管和管理场景；窄屏仍可完成阅读、筛选和审批。
- 不只用颜色表达健康度或风险，必须有文本和图标标签。
- 所有图表提供同数据的文字摘要或表格替代。
- 键盘可访问主要导航、筛选、对话框和确认操作。
- 用户姓名和头像使用飞书用户组件，不直接展示内部 ID。
