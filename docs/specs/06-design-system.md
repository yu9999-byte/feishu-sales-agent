# Web 产品设计系统

状态：`Approved / 2026-09-19`

## 1. 设计判断

Reading this as: 面向销售、主管和管理员的 B2B SaaS 工作产品，采用严肃、可信、数据密集但
不拥挤的语言，沿用项目现有 shadcn/ui 与 Tailwind 体系。

本项目不是营销落地页。设计参数固定为：

- `DESIGN_VARIANCE: 4`：信息结构稳定，允许少量非对称以突出行动优先级。
- `MOTION_INTENSITY: 3`：只使用状态反馈、对话框和轻量过渡，不做装饰性滚动动画。
- `VISUAL_DENSITY: 7`：适合日常销售工作台和分析页面，但保持可扫读间距。

## 2. 现状审计

| 项目 | 当前状态 | 处理决定 |
| --- | --- | --- |
| 设计系统 | 已有 shadcn/ui、Tailwind 与语义变量 | 保留并定制，不增加 Fluent/Carbon 等第二套体系 |
| Web 信息架构 | 仅有脚手架欢迎页 | 按 `01-information-architecture.md` 建立角色导航 |
| 品牌 | 暂无正式 Logo、字库和品牌手册 | 使用“销策 Agent”文字标识，后续品牌输入到位再替换 |
| 色彩 | 脚手架默认主题 | 冷中性色 + 单一蓝色强调，禁止 AI 紫色渐变 |
| 圆角 | 组件默认值未形成规则 | 面板 12px、控件 8px、状态标签全圆角 |
| 动效 | 无产品级约束 | 仅反馈和状态切换，全部尊重 reduced motion |
| 页面状态 | 欢迎页没有业务状态 | 所有业务页实现 loading/empty/error/forbidden/stale/partial |
| 可访问性 | 依赖基础组件 | 补足键盘路径、焦点、文字标签和非颜色状态表达 |

这是 Greenfield 产品外壳，不沿用遗留欢迎页的版式和文案；现有路由、P0 机器人交互和外部
数据字段不被静默改名。

## 3. 视觉令牌

### 3.1 色彩

- 页面底色：冷白或浅冷灰。
- 一级文字：近黑冷灰，不使用纯黑。
- 二级文字：满足 WCAG AA 的中性灰。
- 唯一强调色：企业蓝，用于主按钮、选中导航、链接和键盘焦点。
- 成功、警告、危险只用于真实语义状态，并同时显示图标和文字。
- 单页不切换明暗主题；Phase A 采用固定浅色产品主题。

### 3.2 排版

- 优先使用系统无衬线字体栈，中文与数字同层级对齐。
- 页面标题 24-30px，分区标题 18-20px，正文 14px，辅助文本 12-13px。
- 数字指标使用等宽数字特性；不使用超大营销标题和装饰性斜体。
- 可见文案不得出现无来源的精确数字或虚构客户数据。

### 3.3 间距与形状

- 基础间距 4px，常用间距采用 8/12/16/24/32px。
- 页面内容最大宽度 1440px；桌面侧栏固定，窄屏折叠为抽屉。
- 卡片只用于有独立层级或操作边界的内容，普通分组优先使用留白与分隔线。
- 禁止 Card 嵌套 Card。

## 4. 应用外壳

### 4.1 桌面

```text
顶部：租户名称 / 全局搜索入口 / 当前用户
左侧：按角色过滤的一级导航
主体：面包屑 / 页面标题 / 主要动作 / 页面内容
右侧：仅在上下文助手或详情补充信息需要时出现
```

导航顺序固定为：工作台、客户、商机、跟进、任务、Review、知识与打法、管理。无权限入口
不渲染；服务端仍再次校验。

### 4.2 窄屏

- 小于 768px 时侧栏进入抽屉，主要动作不被隐藏在仅 hover 可见区域。
- 表格优先保留主字段和状态，其余字段通过详情抽屉或横向滚动查看。
- 页面操作保持至少 44px 触控区域。

## 5. 核心组件规则

| 组件 | 规则 |
| --- | --- |
| 导航 | 图标统一使用 Lucide；当前项同时用背景、文字粗细和 `aria-current` 表达 |
| 按钮 | 每个区域只有一个主要动作；危险动作进入确认对话框 |
| 状态标签 | 文字 + 图标 + 颜色，不使用装饰性圆点 |
| 数据列表 | 使用项目官方 Table 能力；长列表必须分页或游标加载 |
| 表单 | 标签在控件上方；帮助文案和字段错误均有固定位置 |
| 对话框 | 焦点锁定、Esc 行为明确，提交中禁止重复操作 |
| 骨架屏 | 形状与最终结构一致，不使用全页旋转图标 |
| 图表 | 同时提供文字摘要；颜色之外必须有标签或纹理区分 |
| 用户 | 姓名和头像使用飞书业务用户组件，不直接显示内部 ID |

## 6. 完整状态模型

每个页面和可独立刷新的区块均使用以下状态：

| 状态 | 表现 | 可用动作 |
| --- | --- | --- |
| `loading` | 与目标布局一致的骨架 | 无重复刷新 |
| `ready` | 完整授权数据 | 业务动作按权限展示 |
| `empty` | 解释空数据原因 | 提供唯一有效的下一步 |
| `error` | 说明失败范围，不暴露内部堆栈 | 可重试时提供重试 |
| `forbidden` | 统一无权提示，不显示资源名称 | 返回安全页面 |
| `stale` | 展示最后更新时间和过期原因 | 手动刷新 |
| `partial` | 标出缺失的数据源或时间段 | 重试失败部分 |

## 7. 无障碍和质量门禁

- 文字和交互控件满足 WCAG AA；键盘焦点清晰可见。
- 主要流程可仅用键盘完成；图标按钮有可访问名称。
- 动画不是理解内容的前提，`prefers-reduced-motion` 下关闭非必要过渡。
- 页面在 360px、768px、1280px 三个视口完成布局检查。
- 所有按钮文案保持单行；禁止用颜色单独表达风险和健康度。
- 可见中文文案提交前人工通读，禁止营销空话、占位文案和虚构数据。

## 8. Phase A 页面验收

1. 四类角色看到符合权限的导航和工作台入口。
2. 未授权 URL 显示统一 forbidden 状态，不能泄露资源标题。
3. loading、empty、error、stale 和 partial 可通过受控测试状态逐一验证。
4. 桌面和窄屏均能完成导航；键盘可访问侧栏、用户菜单和主要动作。
5. 页面只使用现有 shadcn/Tailwind 和 Lucide，不引入第二套设计系统。
