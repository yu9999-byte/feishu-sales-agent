# 客户沟通内容准备 Agent v1 SDD

日期：2026-10-07  
状态：`Implemented / Automated Green / UI pending`

关联路线：`P1-PROGRESS / COP-023..029`。关联测试：
[客户沟通内容准备 Agent v1 TDD](30-customer-communication-preparation-tdd.md)。

## 1. 产品目标

销售已经能从单客户拜访攻略看到客户、商机、历史跟进、风险、问题和议程，但仍需要自己把
这些事实整理成一次可用的沟通方案。客户沟通内容准备 Agent v1 在攻略之上继续完成：明确本次
沟通目标、给出沟通角度、整理重点问题、列出应准备的材料，并生成可编辑的飞书消息和邮件
草稿。

v1 只生成预览，不发送消息或邮件，不上传文件，不创建任务，也不修改客户、商机和跟进。
所有客户判断必须引用攻略中的客户、商机或跟进来源；没有可信资料库时只输出“材料待补充”，
不得编造案例、报价、产品能力、文档链接或附件。

## 2. 用户入口和结果

- 拜访准备页新增“准备沟通内容”入口，进入
  `/customers/:customerRecordId/communication`。
- 只读 API：
  `GET /api/platform/customer-communications/:customerRecordId`。
- 页面展示本次沟通目标、推荐角度、重点问题、材料准备清单、飞书消息草稿和邮件草稿。
- 每个目标、角度和材料建议都带来源引用，可回到原客户、商机或跟进记录核对。
- 草稿明确标记为“仅预览、可编辑、尚未发送”；v1 页面不提供发送或写回按钮。

## 3. 输入与事实边界

- 服务必须复用 `CustomerVisitBriefingService`，只消费它按精确 record 关系形成的攻略结果。
- 输入只包含当前租户集成、当前销售 `open_id`、URL 客户 record ID、参考日期和时区。
- `empty` 和 `unavailable` 攻略不生成沟通目标、材料或草稿，避免泄露或猜测客户信息。
- `partial` 攻略可以保留已证明内容，但沟通方案必须保持 `partial` 并原样呈现覆盖警告。
- 同名客户、同名商机、聊天记忆、普通任务标题和未引用的外部知识均不得形成事实。

## 4. 沟通目标、角度和问题

- 有进行中商机时，目标优先围绕最高优先级商机的真实建议、风险或缺口形成。
- 没有进行中商机时，只能以“确认客户当前变化和是否存在新需求”为目标，不得假造商机。
- 推荐角度最多 3 个，依次覆盖客户现状、商机推进/风险和双方下一步；没有对应事实时省略或
  使用明确的待确认表达。
- 重点问题复用攻略的待确认问题，保持原问题、原因和商机 record ID，不改写成既成事实。
- 目标和角度至少引用一个来源；无法形成来源引用的建议不得返回。

## 5. 材料建议

- v1 不接入真实飞书文档、知识库、案例库、报价库或产品资料库。
- 材料清单根据已证明场景推荐“需要准备什么”，例如客户背景摘要、需求确认清单、方案概览、
  案例、报价边界或会议议程。
- 每项材料统一返回 `material_pending`，页面显示“材料待补充”。
- 材料项只包含标题、用途、选择依据和来源键，不包含 URL、文件 token、附件 ID 或伪造内容。
- 已知金额只能作为“报价边界校对”的输入，不得直接生成价格、折扣或对客户的报价承诺。

## 6. 草稿契约

- 固定生成两份草稿：飞书消息和邮件；邮件可包含主题，飞书消息主题为 `null`。
- 草稿只能拼接来源中明确存在的客户名、联系人、客户摘要、商机名、风险、建议和待确认问题。
- 联系人缺失时使用中性称呼，不虚构姓名；销售姓名、产品名、案例名和价格缺失时不得补造。
- 每份草稿返回引用来源键、`editable: true` 和 `execution: preview_only`。
- 页面可以复制或人工编辑展示内容，但 v1 不调用发送 API；复制也不构成已发送证据。

## 7. 身份、权限和副作用

- 必须具有有效飞书 Web 会话、当前租户 active 成员身份。
- 服务端依次要求 `customer:read`、`opportunity:read` 和 `followup:read`。
- 平台会话与认证会话必须属于同一租户、成员和 `open_id`；否则 fail closed。
- Controller 只能把当前认证成员的 `open_id` 和 URL 客户 ID 传给服务。
- v1 不写 Base、Task、控制库、记忆或审计业务事件，不触发机器人、邮件、定时器或主管通知。

## 8. 状态和页面

- `ready`：攻略完整，沟通方案与两份草稿可预览。
- `partial`：保留可证明内容，同时展示来源不完整警告。
- `empty`：客户不存在或不在本人可见范围，不生成任何客户内容。
- `unavailable`：身份、日期、时区、集成或攻略来源不可可靠使用。
- 页面覆盖 loading、error、empty、partial、unavailable 和 ready；任一状态都不得出现发送按钮。

## 9. 验收标准

- `COP-023`：只用精确客户 ID 调用攻略服务，状态和本人范围不回退。
- `COP-024`：目标、角度和问题均由真实攻略事实生成，目标/角度来源可追溯。
- `COP-025`：材料只返回待补充清单，不包含虚构链接、文件或报价内容。
- `COP-026`：飞书和邮件草稿可编辑、仅预览，缺字段时使用中性表达。
- `COP-027`：三权限、会话、成员、租户和集成失败路径均 fail closed。
- `COP-028`：页面完整覆盖各状态并能回到来源记录，不提供真实发送入口。
- `COP-029`：服务和页面不产生 Base、Task、消息、邮件、控制库或调度副作用。
