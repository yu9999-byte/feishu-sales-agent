# 角色与数据权限规格

状态：`Approved / 2026-09-19`

## 1. 授权模型

授权判定由以下条件共同决定：

```text
tenant membership
+ role permissions
+ reporting scope
+ resource ownership/share grants
+ action context
```

前端隐藏仅用于体验，服务端是权限权威。任何 LLM 上下文构建、搜索索引查询和外部工具调用
都必须使用同一授权结果。

## 2. 基础角色

| 角色 | 默认数据范围 | 关键权限 |
| --- | --- | --- |
| `sales` | 本人负责或明确共享的客户/商机 | 录入、编辑本人草案、确认本人写入、看本人报告 |
| `manager` | 本人及递归下属，外加明确共享资源 | 团队 Review、风险处理、分配团队任务 |
| `executive` | 租户全量业务数据，只读为默认 | 经营看板、全局 Review、下钻证据 |
| `admin` | 租户全量 | 配置、授权、审核发布、审计；业务修改仍需单独权限 |

管理员身份不自动意味着可以代表销售确认业务跟进或向客户发送内容。

| 能力 | 销售 | 主管 | 高管 | 管理员 |

## 4. 组织和共享

- 汇报关系默认来自飞书组织架构，可由管理员添加有效期明确的矩阵汇报关系。
- 主管范围按有效汇报边计算；关系变化后新请求立即按新范围处理。
- 商机协作使用资源共享授权，至少包含查看、编辑、任务协作三种级别。
- 临时授权必须有开始时间、结束时间、授权人、原因和审计记录，到期自动失效。
- 禁止通过把用户加入群聊来隐式授予客户或商机权限。

## 5. 推送权限

| 事件 | 默认收件人 | 条件 |
| --- | --- | --- |
| 跟进保存成功 | 销售本人 | 每次确认后 |
| 新需求/需要支持 | 本人；售前/产品等被请求协作者 | 已确认的需求有证据、策略启用，且销售确认具体支持对象后 |
| 高风险信号 | 本人+直属主管 | 达到策略阈值且去重窗口已过 |
| 关键里程碑 | 本人；团队群可配置 | 销售确认里程碑及目标群，群内可见范围合法 |
| 竞品提及 | 本人；主管/市场可配置 | 已确认事实有原文证据，策略启用且收件人有权访问 |
| 高优先任务逾期 | 本人；主管可配置 | 到期且未完成 |

主管收到的卡片不得包含其数据范围外的其他客户名称、金额或证据。
任何跨角色推送都不发送未确认草案；收件人映射、共享权限和敏感字段裁剪在发送时重新校验。
客户所在群并不自动成为授权范围；普通跟进不群发。推送失败不回滚已成功的业务写入，
通过租户和事件指纹去重后单独重试。

## 6. 拒绝与审计

- 权限拒绝统一返回无权访问，不区分“资源不存在”和“资源存在但无权”。
- 审计至少记录租户、行为人、角色快照、动作、资源类型/内部引用、结果、策略版本和时间。
- 审计详情不得保存 Secret、Token、完整认证头或未经必要脱敏的客户原文。
- 导出、批量查询、权限变更、代操作和 Playbook 发布属于重点审计事件。
