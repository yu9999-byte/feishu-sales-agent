# Agent 运行健康检查 SDD

状态：本地实现及验证完成，2026-10-20；正式运行保障仍待环境验收。关联待办：持续在线与本地运行恢复。

产品/业务：运维需要区分进程存活和业务控制库就绪。只占用端口不代表可用，数据库故障不能返回就绪成功。探测不读取业务正文、不调用飞书/模型、不创建业务记录。

交互/API：GET /api/health/live 返回 200 与 status=alive。GET /api/health/ready 检查当前控制库连接和迁移账本，返回 200 ready 或 503 not_ready；响应仅含固定依赖状态及 UTC 检查时间，不暴露连接地址、数据库错误、身份或凭证。存活不依赖数据库。就绪不证明飞书、模型、调度准时或外部记忆可用。

技术：复用 ControlDatabaseModule 的 Sql；以 READ ONLY 事务查询迁移账本，要求当前运行所需的全部 29 个迁移名存在（SDD 51 新增 032），不校验迁移文件校验和。事务内 SET LOCAL statement_timeout=1500ms，由数据库终止超时语句；HTTP 探测另设 2 秒截止时间。并发请求共享一次在途检查；HTTP 超时后保留共享结果，直到底层操作结束才释放，避免失联时不断增加挂起查询。响应完成后清理定时器，底层操作结束后允许重新检查。就绪不做 DDL 或自动迁移，不把驱动 cancel() 当作可靠的无未处理异常取消机制。

启动：start-agent-runtime.ps1 保留原进程冲突检查，检查现有或新启动实例的 /api/health/ready，限定等待时间。未就绪明确失败且不盲目停止已有进程。测试使用另一个端口的独立进程，禁止因此重启生产式长连接。

TDD：先红覆盖存活无 DB 查询、全部迁移就绪、缺迁移/DB 异常/超时返回失败、错误脱敏、并发共享、失败恢复与 HTTP 状态；再实现。隔离 PostgreSQL HTTP 集成覆盖空/完整迁移账本、缺单项迁移、实际锁等待超时及恢复、关闭连接。完整 runtime 另行验证停库时就绪失败而存活成功、启动脚本拒绝假成功且不杀已有进程、数据库恢复后重新就绪。相关回归、三套类型、Lint、双构建通过。外部运行保障仍未验收。
