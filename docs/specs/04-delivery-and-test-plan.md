# 分阶段交付与测试计划

状态：`Approved / 2026-09-19`

## 1. 交付策略

Goal v3 是完整产品目标，但采用可独立 UI 验收的纵向切片。每一阶段结束都必须留下可运行
产品，不允许先搭大量不可用底层再一次性联调。

## 2. 阶段划分

### Phase A：平台基线与产品外壳

范围：租户成员、四类角色、汇报关系、数据范围、审计扩展、数据源端口、Web 导航与工作台
外壳、设计系统。

UI 验收：四类账号登录看到不同导航；销售不能访问主管/管理员页面；跨租户资源链接被拒绝。

### Phase B：Sales Behavior Agent

按以下切片交付：

0. B0 对话基座：AI 优先的自然聊天、销售方法问答、短期上下文、歧义澄清与跟进路由；不以
   普通文本默认写入业务系统。
1. 原聊天卡片表单/文本生成、卡内编辑、保存前可用性提示、任务预览与一次确认。
2. 结果＋任务卡、无任务/部分失败/重复回调、条件性项目推进质检卡。
3. 语音输入。
4. 妙记/会议纪要输入。
5. 飞书文档输入。
6. 跨角色策略推送、任务状态建议/确认回收和提醒。
7. 个人日报。

UI 验收：普通问答无跟进副作用；每种明确录入来源都把标准草案发回原聊天；编辑后同卡缺口提示和任务预览变化；一次确认后
Base/Task/本人结果及条件通知正确且无重复副作用；Web UI 通过不能替代飞书聊天验收。

### Phase C：Customer & Opportunity Agent

范围：客户/商机列表与详情、时间线、决策链、竞争态势、拜访攻略、项目质检、健康度、风险、
下一步、赢单概率和预计成交时间。

UI 验收：销售与主管看到不同范围；从风险卡片下钻到证据；预测在样本不足时正确降级。

### Phase D：Sia 深化

范围：在 B0 对话入口之上接企业知识索引、ACL、产品/客户/商机/任务/打法问答、来源引用、多轮上下文、操作预览
和确认执行。

UI 验收：权限内回答有引用；越权问题不泄漏；无来源时拒绝编造；写操作确认后执行一次。

### Phase E：Review Agent

范围：个人/团队日报周报、Weekly Review、人员效能、目标、Commit、AI Commit、Gap、趋势、
风险项目和证据下钻。

UI 验收：报告数据与源记录对账；主管只能看团队；定时任务重试不重复推送。

### Phase F：Best Practice Agent

范围：赢单/丢单样本、候选规律、Playbook 编辑审核、版本发布、灰度和效果事件。

UI 验收：样本不足不生成；AI 建议未经审核不可见于已发布版本；旧版本可审计回读。

### Phase G：产品化与多企业验收

范围：租户自助配置、正式部署、固定 HTTPS、健康/告警、备份恢复、性能、安全和两个真实租户
验收。

UI 验收：关闭开发机后两个企业仍可独立运行，数据、索引、报告、通知和审计不串租户。

## 3. 每个切片的 TDD 证据

| 阶段 | 必须保存的证据 |
| --- | --- |
| Spec | 需求编号、场景、异常、权限、接口/Schema、验收条件 |
| Red | 测试命令、失败测试名、预期失败原因 |
| Green | 同一测试通过以及受影响回归通过 |
| Refactor | 类型、Lint、构建和全量相关套件通过 |
| UI | 真实账号、输入、消息/页面、外部记录 ID 和审计 trace |

## 4. 测试层级

- **单元测试**：评分规则、状态机、授权判定、去重、事件路由、Schema 校验。
- **契约测试**：共享 API、飞书事件/卡片、Base/Task/Docs/Minutes 适配器、LLM Schema。
- **集成测试**：真实 Postgres、迁移、Repository、模块编排和失败恢复。
- **固定评测集**：跟进抽取、内容生成、质检、风险、问答引用和预测降级。
- **权限负向测试**：跨租户、跨汇报线、过期授权、猜测 ID、搜索和 RAG 越权。
- **浏览器测试**：路由、页面状态、筛选、编辑、确认、角色导航和响应式布局。
- **飞书 UI 测试**：消息、卡片表单、按钮、语音/妙记/文档入口、任务和通知。
- **运行测试**：重启恢复、外部 429/5xx、定时任务幂等、备份恢复和告警。

## 5. LLM 评测规则

- 评测样本不得包含真实客户隐私，使用经批准的合成或脱敏样本。
- 抽取类指标至少包含字段精确率/召回率、日期和金额正确性、证据可定位率。
- 生成类由事实一致性、结构完整性、可执行性和禁止臆造四个维度评估。
- 风险和质检既测命中也测误报；阈值在对应阶段规格中冻结。
- RAG 测引用正确性、无答案拒答、权限过滤和多轮指代。
- 免费模型拥堵属于运行失败，不得用跳过评测或 Mock 结果代替。

## 6. 完成定义

单个需求只有同时满足以下条件才标记 `UI Verified`：

1. 规格为 Approved，且追踪矩阵有唯一需求编号。
2. Red/Green 证据真实存在。
3. 正常、异常、权限和幂等测试通过。
4. 相关 P0 回归无倒退。
5. 真实 UI 验收完成并能回读外部副作用。
6. Markdown、运行说明和审计证据同步更新。
