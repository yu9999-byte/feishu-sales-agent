# 客户沟通准备包统一入口 SDD

状态：Goal v1 已确认并启动；实现中，2026-10-19。

## 产品与业务
销售通过统一飞书私聊提出未来客户沟通准备，复用 CustomerVisitBriefingService、CustomerCommunicationPreparationService 与资料 ACL。请求不是已发生沟通，不进入跟进写入流程。准备包事实带来源、建议单独标识，无资料或来源失败明确降级。Web 复用现有沟通准备页并承接编辑/复制。

## 交互
识别客户、拜访/沟通时间、目的。同名客户只列本人可见候选并要求选择，不按名称猜 ID。缺客户先询问客户，多轮仅承接同租户、本人、同聊天且有效期内的准备请求。取消、超时、切换话题不复用陈旧选择。目的与时间为用户条件，不自动视为业务事实。

## 技术切片
PREP-001：先建立无副作用的结构化请求解析契约；trim/长度/明确时区校验，空日期或目的允许后续澄清，缺客户拒绝执行。所有识别结果必须经过该边界，不信任模型输出的客户 ID 或来源事实。
PREP-002：本人可见客户精确匹配、同名澄清与范围隔离。
PREP-003：持久多轮准备状态，沿用入站事件幂等、审计与有界上下文，不能借用跟进草案状态。
PREP-004：组合现有准备与拜访服务，生成有来源的摘要及 Web 入口；不自动发送邀约/建任务/改业务。
PREP-005：接入统一自然意图与工作流，优先保护进行中的跟进确认流程。
PREP-006：Web 接收准备条件、查看完整结果及本地编辑复制，服务端重复校验本人读取权限。

## 验证
先失败测试再实现，覆盖明确/缺失/同名客户、多轮、来源失败、无资料、跨租户用户聊天隔离、重复请求。测试不得调用真实外部写入。真实聊天消息额度已满，真实 UI 阻塞独立记录，不伪称通过。整体仍须单元/集成/类型/Lint/双构建与真实 UI。

## 第一切片进展

请求契约与纯客户匹配边界 11 项通过。匹配只接受服务端可见候选的精确名称，稳定去重并返回同名候选，不接受模型 ID、不模糊猜客户。访问服务在读取前校验 active integration、成员身份和 customer/opportunity/followup/playbook read 权限，并将来源告警映射为 partial、读取异常映射为 unavailable；每次解析都重新读取，避免信任过期候选。PREP-003 持久多轮及 PREP-004..006 组合与聊天/Web 接入仍待开发，不能把权限接入通过写成统一入口已实现。

## PREP-002 读取边界

客户解析服务先验证 active integration、active member 与会话 tenant/member/openId 一致，要求 customer/opportunity/followup/playbook 四读取权限，再调用 readOpportunityPortfolio(integration, actorOpenId)。未授权零业务读取。仅返回精确匹配候选和来源是否 partial，不带其他客户或上游异常正文。来源失败返回 unavailable，不伪装 not_found。后续选择候选必须重新读取可见范围校验，不能仅相信旧候选 ID。
