## 业务与判定规则
业务日期按租户时区。今日待跟进来自明确跟进计划到期，不以“客户存在”推断需要联系；即将到期任务采用现有今日/明日范围，已完成任务排除。停滞沿用现有 14 天规则；信息不完整沿用现有 gaps；风险沿用已有 risks 及其 evidenceIds。同一来源可有多个原因，但合并为一条可处理事项，保留全部证据。无时间的建议由规则给出建议日期并标明建议，不伪装成客户承诺。数据未覆盖则保留缺口。

## 交互
飞书：输入 → 草案生成中 → 完整可编辑表单+质检 → 一次确认 → 执行中 → 结果/重试/编辑。已处理回调保留当前状态，不新发结果卡。今日行动卡显示原因、证据、建议时间，链接 Web 详情；快捷操作不得偷偷发送或建任务。
Web：今日行动列表按紧急程度和稳定来源 ID 排序；展示覆盖范围、空态、加载和错误；事项详情显示原始来源链接、全部提醒原因和四项操作。提交中禁重复点击，失败保留输入，刷新回读持久状态。
