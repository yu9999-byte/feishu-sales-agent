# 客户洞察与拜访准备 Agent v1 SDD

日期：2026-10-07

关联路线：`P1-PROGRESS / COP-017..022`。关联测试：
[客户洞察与拜访准备 Agent v1 TDD](28-customer-visit-briefing-tdd.md)。

## 1. 产品目标

销售从客户组合选择一个本人可见客户后，Agent 基于真实客户、商机、历史跟进和已确认任务
证据形成一份会前攻略，帮助销售在拜访或沟通前快速知道：客户是谁、最近发生了什么、有哪些
相关商机和风险、本次应该确认哪些问题、会议最好按什么顺序推进。

v1 不是模型自由生成的客户画像，也不是完整 CRM 客户 360。所有结论都必须能回到本人范围的
明确记录；信息缺失时生成“待确认问题”，而不是补造事实。

## 2. 用户入口和结果

- 客户组合卡新增“准备拜访”，进入 `/customers/:customerRecordId/briefing`。
- 只读 API：`GET /api/platform/customer-briefings/:customerRecordId`。
- 页面展示客户名称、当前联系人、最新客户摘要、最近可信跟进时间和数据状态。
- 相关商机同时保留进行中和已结束记录；进行中商机复用决策 Agent 的风险、缺口和建议。
- 最近跟进最多展示 10 条，按可信沟通时间倒序；没有时间的记录排在有时间记录之后。
- 生成会前待确认问题和建议议程，问题必须由缺失字段或真实风险触发。
- 页面明确说明建议尚未执行，不会联系客户、创建任务或修改业务记录。

## 3. 身份、权限和范围

- 必须具有有效飞书 Web 会话、当前租户 active 成员身份。
- 服务端依次要求 `customer:read`、`opportunity:read` 和 `followup:read`。
- 客户、商机和跟进均通过当前销售 `open_id` 读取本人范围；缺少负责人映射时不进行无范围
  查询。
- URL 中的客户 record ID 只作为本人组合内的精确匹配条件；找不到时返回空结果，不暴露该
  记录是否属于其他销售或租户。
- 认证会话、平台会话或租户集成不一致时 fail closed，业务网关零调用或攻略服务零调用。

## 4. 事实关联规则

- 客户以精确 `recordId` 匹配。
- 商机仅以 `customerRecordId` 精确关联客户，不按客户名或商机名猜测。
- 跟进有 `customerRecordId` 时只接受该字段精确命中；即使商机链接属于当前客户，冲突的客户
  链接也不能被覆盖。只有 `customerRecordId === null` 时，才允许通过精确属于该客户商机的
  `opportunityRecordId` 关联。
- 同名客户、同名商机、标题相似任务均不形成关联。
- 进行中/状态待确认商机使用 `OpportunityDecisionService` 的确定性风险、缺口、健康度和建议；
  赢单、丢单、关闭商机只作为历史背景，不重新生成推进风险。
- 客户只返回来源 record ID、链接和版本；前端可回到原始记录核对。

## 5. 待确认问题与议程

问题按以下事实缺口生成并去重：

- 联系人缺失：确认本次参会人、关键联系人和角色；
- 客户摘要缺失：确认客户当前目标、变化和最关注问题；
- 商机进展、金额、下一步或截止时间缺失：逐项形成业务问题；
- 下一步逾期、长期无跟进、无跟进证据、生命周期未知、已确认任务逾期/变更：形成风险核对
  问题，并保留相关商机 record ID；
- 所有问题都只要求销售或客户确认，不直接更新记录。

议程固定使用事实驱动的三段式：客户目标和变化、相关商机与阻塞、双方下一步/责任人/时间。
没有相关商机时改为确认客户需求和是否存在新机会；没有历史跟进时明确先补充当前背景。

## 6. 状态和覆盖

- `ready`：客户存在且客户/商机/跟进及任务决策来源完整。
- `partial`：客户存在，保留可证明内容，但至少一个来源或任务证据不完整。
- `empty`：客户不在当前销售可见组合中；不区分不存在和无权限。
- `unavailable`：身份、日期/时区、组合网关或关键客户来源不可可靠使用。

覆盖范围分别说明客户、商机、跟进和任务承诺。分页不完整或负责人字段缺失必须映射为 warning，
不能由模型记忆、聊天内容或其他客户数据补齐。

## 7. 副作用边界

v1 完全只读：不修改客户/商机/跟进/任务，不创建任务，不保存任务观察快照，不联系客户，不发
飞书消息，不触发主管通知，不调用 S4 执行入口，不启用 cron。任何后续“发送会前材料”“创建
会后任务”“更新商机”都必须另行通过预览、人工确认、幂等执行、回读和审计。

## 8. 验收标准

- 本人范围、三权限、跨租户和不可见 record ID 均有失败关闭测试。
- 商机/跟进只按 record 关系关联；同名文本不得串客户。
- 进行中商机有风险和建议，关闭商机只作背景；未知金额保持 `null`。
- 最近跟进稳定排序并限制为 10 条；无时间记录不伪造时间。
- 待确认问题和议程只来自真实缺口/风险，并保持未执行。
- 页面覆盖 loading、error、empty、partial、unavailable 和正常态。
- 自动化、三套 TypeScript、Lint、双构建、迁移幂等、启动冒烟和 `git diff --check` 全部通过
  后，状态只能提升为 `Automated Green / UI pending`。
