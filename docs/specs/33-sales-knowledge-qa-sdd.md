## 1. 产品目标

销售可以在“销售agent”私聊中直接询问产品能力、客户沟通与拜访准备、数据安全和权限边界。
Agent 不再用模型常识直接回答企业资料问题，而是从当前租户明确批准、当前销售本人可访问的
飞书资料中查找证据并返回可核验答案。

v1 采用证据型回答：直接展示最相关的真实原文摘录、文档标题、引用位置、版本、适用边界和
原文链接。没有可信证据时明确说明“未找到可信答案”，不得补写产品能力、案例、价格、承诺或
安全结论。

## 2. 用户入口

- 复用唯一“销售agent”私聊，不增加第二个机器人。
- 当意图为高置信度 `sales_qa` 时进入知识问答；问候、客户事实、商机查询、跟进记录和写操作
  继续走原有路由。
- 示例问题：“销售 Agent 能做什么”“拜访客户前要准备什么”“资料权限怎么控制”。
- v1 不新增 Web 输入页，真实 UI 按用户要求保持 pending。

## 3. 数据与权限边界

1. 只读取当前租户 `base_mapping.knowledge.sources` 中逐条配置的 Docx/Wiki 节点。
2. 每次问题都重新执行机器人只读和当前销售本人 ACL 检查，不复用其他销售的检索结果。
3. 只有当前平台会话具备 `playbook:read` 才允许读取资料。
4. bot/app、群、部门、其他用户或互联网公开链接不能推导为销售本人可读。
5. 不扫描整个知识空间、个人云盘、邮件、互联网或未配置附件。

## 4. 检索与回答

- 查询只使用用户当前问题，不把模型回复、长期记忆或其他客户数据当作资料事实。
- 以管理员关键词、真实标题和正文短语命中计算确定性分数，按分数、标题、来源 ID 稳定排序。
- 每个来源只返回一个最相关段落，最多 3 个来源；摘录保持原文，单条长度受限。
- 回答由受控模板组合真实摘录，不要求模型改写，因此不会生成来源中不存在的主张。
- 每条证据包含：标题、资料类型、原文链接、匹配原因、原文摘录、正文段落、资料版本、适用
  边界和 `accessVerified=true`。

## 5. 状态契约

- `answered`：至少一条白名单来源通过 ACL 且与问题有真实命中。
- `not_configured`：当前租户没有有效资料白名单。
- `no_trusted_match`：已检查可用来源，但问题没有可信命中。
- `partial`：已返回可信答案，但部分来源失效或无法核验。
- `unavailable`：配置存在，但全部来源读取或权限核验不可用。

`not_configured`、`no_trusted_match`、`unavailable` 都不得退回模型通用答案。`partial` 只展示已
验证来源，并明确部分资料不可用。

## 6. 审计与副作用

- 审计只记录问题路由、状态、配置/检查/可信结果数量和稳定来源 ID，不保存文档正文或摘录。
- 不写客户、商机、跟进、任务、控制库、记忆或飞书文档。
- 不发送给客户、不建任务、不修改权限、不启用调度器。

## 7. 验收标准

- `SIA-001`：高置信度 `sales_qa` 进入真实资料问答，不采用模型生成的企业事实回复。
- `SIA-002`：租户白名单、销售本人 ACL 和 `playbook:read` 三层门禁缺一不可。
- `SIA-003`：成功答案最多 3 条，含真实摘录、引用、版本、边界和原文链接。
- `SIA-004`：未配置、无命中、部分失败和全部不可用均有诚实、可区分结果。
- `SIA-005`：失败关闭；无可信证据时不生成答案，且全部路径零业务副作用。
- `SIA-006`：专项、跨层、全量、Postgres、类型、Lint、构建、迁移幂等和启动冒烟通过；项目
  文档和 GitHub milestone 同步，真实 UI 保持 pending。
