# 跟进计划与业务上下文读取 TDD

状态：`Approved / Goal v2 / partial Green 2026-09-25`

关联 SDD：[跟进计划与业务上下文读取 SDD](14-followup-context-read-sdd.md)。

## 1. 测试原则

先建立能证明契约缺失的 Red 场景，再实现最小查询端口和 LangGraph 注入。测试使用合成或脱敏
数据，不调用真实客户写入；所有测试必须断言查询阶段没有 Base/Task/控制库业务写入。首轮 Red
已证明读取服务缺失；Green 已覆盖上下文编排、本人范围查询、文本跟进注入、来源持久化和
商机/跟进行动字段冲突保留的部分场景。

## 2. Red/Green 验收矩阵

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| CTX-001 | 唯一客户和商机匹配 | 返回标准领域模型、来源引用和当前任务 |
| CTX-002 | 客户无匹配 | 返回澄清所需候选为空，不进入写入节点 |
| CTX-003 | 客户多匹配 | 返回全部授权候选并暂停自动选择 |
| CTX-004 | 跨租户 record/token | 结果不可见，审计拒绝原因，不泄漏字段 |
| CTX-005 | 当前销售无权限 | 返回权限不足警告，不把空结果误报为没有数据 |
| CTX-006 | 客户/商机来源版本冲突 | 保留冲突来源和较新/较旧标记，不静默覆盖 |
| CTX-007 | 任务已逾期或状态变化 | 只读返回状态，生成建议输入，不更新任务 |
| CTX-008 | 查询超时/部分失败 | 明确降级状态，模型不得声称已读取完整上下文 |
| CTX-009 | 同一请求重复读取 | 读取幂等且不产生业务写入或重复任务 |
| CTX-010 | 上下文注入草稿节点 | 草稿证据只引用授权来源，Mem0 不替代业务事实 |
| CTX-011 | 查询阶段执行确认回调 | 未通过确认门不得写 Base 或 Task |
| CTX-012 | 两租户相同关键词 | 结果严格隔离，不能因缓存或候选 ID 串租户 |

npm run type:check:client

npm run eslint
npm run build:agent

写成已通过。

## 4. UI 验收

真实飞书/Web 验收至少包括：唯一匹配正常草稿、无匹配澄清、多匹配候选、权限不足提示、
查询失败降级和确认前零副作用。每条记录输入、租户、操作者、可见上下文、来源链接、审计
trace 和 Base/Task 回读结果。
