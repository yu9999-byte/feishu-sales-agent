## 1. 产品目标

把已在机器人和 API 中可用的商机决策能力变成销售可直接打开的 Web 工作台：

- `/opportunities` 回答“最该推进哪个商机、为什么、下一步是什么”；
- `/customers` 按客户汇总进行中商机、风险、已知金额和首要建议；
- 两页复用同一个本人范围决策契约，不建立第二套业务事实。

## 2. 需求契约

### COP-008 客户组合摘要

- 返回当前销售可见的全部客户，即使客户暂无进行中商机也保留。
- 只汇总具有显式 `customerRecordId` 的进行中或状态待确认商机。
- 客户的商机数、高风险数、已知预计金额、最高优先级和建议由已排序商机结果派生。
- 没有任何已知金额时返回 `null`，不用 `0` 伪装“已知为零”。

### COP-009 商机主从式决策面

- 左侧按既有确定性优先级排序显示商机，右侧显示当前选中商机。
- 详情展示当前进展、预计金额、最近跟进、原定下一步、风险、缺口、建议、
  Agent 已确认任务承诺和决策证据。
- 选中记录失效时回退到当前第一优先商机；列表项支持键盘焦点和按钮语义。

### COP-010 数据状态和覆盖提示

- 两页都有加载、错误、空数据、部分数据和来源不可用状态。
- 页面显示客户、商机、跟进和任务承诺的覆盖范围；不用空白或虚构数据掩盖缺口。
- 客户页明确标记为“客户组合摘要 v1”，不宣称为完整 CRM 360。

### COP-011 只读与可追溯边界

- Web 仅调用 `GET /api/platform/opportunity-decisions`，不创建任务、不更新商机、不联系客户。
- 飞书 Base 或任务链接在新窗口打开，且只使用后端返回的真实 URL。
- 不按客户名、商机标题或金额相似度猜测关联。

## 3. 页面结构

`/opportunities` 使用高密度、证据优先的主从式工作台；`/customers` 使用客户卡片组合。
两页延续现有单浅色主题、蓝色主色、系统中文字体和现有 shadcn/Tailwind 语义 token，
不引入第二套设计系统、营销落地页结构或装饰动画。

## 4. 当前非目标

- 完整客户 360，包括全量活动时间线、文档、会议、联系人网络和多渠道沟通。
- 独立商机编辑页、任务创建或客户消息发送。
- 主管团队客户/商机组合排序和管理动作。
- 真实飞书或 Web UI 验收。自动化、生产构建和启动冒烟不能替代 UI 证据。
