## 多企业 SaaS 与 P0 Demo 的关系

- 产品目标：同一套服务可处理多个飞书企业安装实例。
- P0 真实验收：先在一个测试企业的自建应用中跑通端到端流程。
- P0 自动验收：使用两个模拟 `tenant_id` 验证配置、会话、幂等键和数据访问相互隔离。
- P0 不包含：飞书应用市场上架、商业授权、计费、企业自助安装和管理员配置页面。

当前自建应用只能服务其所属企业，不能单独证明跨企业分发能力。生产化时需要迁移到可被
多个企业安装的飞书商店/ISV 应用形态，或提供每企业独立应用配置。

## 数据源决策

P0 每个企业绑定自己的多维表格，后端通过以下映射访问数据：

```text
tenant_id -> data_source_config -> base_token -> customer/opportunity/followup tables
```

真实演示只创建一个 Demo Base。未来 CRM、数据库和其他 Base 通过统一数据源适配器接入，
不把某个具体 Base 的字段名写死在 Agent 推理逻辑中。

## 2026-10-16 决策：可信闭环与今日行动中心
复用已有 Agent 与执行器，行动中心是本人业务信号的聚合与操作入口，不新增 Agent。持久处理状态按信号版本隔离，旧处理不能屏蔽新风险；生成跟进/任务只进入人工确认。真实发送和 Base/Task 写入继续单独确认。完整契约见 specs/47-trusted-followup-action-center-sdd.md。

2026-10-16：飞书今日行动快捷操作采用独立严格回调契约；稳定键绑定事项版本与修订，同一点击重放不得重新计算提醒时间，业务写入仍走既有人工确认。

2026-10-17：主动提醒首次消息载荷随 claim 原子冻结，重试只发送账本载荷；快捷回调必须精确匹配该载荷中的按钮 value，旧无载荷卡片不开放新快捷操作。迁移 024 与相关单元/集成验证已通过。

### 卡片状态回显恢复切片（2026-10-17）
- 设计：基于已发送卡片冻结载荷与当前事项状态生成原卡片替换内容；保留其他事项与工作台入口，已处理/稍后提醒事项移除旧操作按钮。
- 恢复：回调重试重放持久操作结果，再按最新状态重建卡片；不新增消息、不重复业务写入。卡片返回失败仅影响展示，保留原操作键供重试。
- 验收：状态渲染覆盖多事项、旧版本隔离和重复重建；真实卡片展示仍待真实账号验收。

### 到期提醒调度切片（2026-10-17）
- 到期提醒沿用现有单租户、单成员、单收件人 rollout 与发送开关；task_action 启用时，在每次调度读取到期 snoozed 状态。
- 重新读取可见事项并精确匹配版本；事项失效、来源不可用或已处理时不发送。投递键由事项 ID、版本与状态 revision 组成，失败重试不提前消费提醒，未知投递由现有账本冻结。
- 普通每日摘要过滤已处理和稍后提醒事项，避免绕过提醒时间。每条提醒包含原因、证据、建议动作与完成日期。
- 验收先覆盖纯规划去重、过期版本和未到期过滤，再接生产调度并验证模块装配；真实发送单独确认。

### 完整行动摘要切片（2026-10-17）
- 飞书每日 task_action 摘要复用 TodayActionService，覆盖客户跟进、任务与商机信号，并读取持久状态过滤已处理/稍后提醒项。
- 每条展示原因、证据、建议动作、建议完成日期；来源降级明确显示。保持本人权限、现有 rollout、投递幂等与人工确认边界。
- 本切片先测试摘要内容与状态过滤，再接生产 runner；聊天业务草案快捷操作继续单独实现，不直接写业务数据。

### 聊天生成跟进入口切片
- 受冻结卡片回调、本人身份及 followup:create-own 权限约束；重新核对可见事项与版本。
- 创建确定性 PendingAction，复用现有真实沟通输入表单、质量检查、完整确认；建议动作不得伪装为已发生沟通。
- 替换原消息为输入表单，不发送新卡片；重复点击保留同一草案及当前内容，过期或已推进草案不得重置。

跟进快捷入口设计修订：保留多事项摘要，使用既有 sendConfirmationCard 的 action.id:confirmation-card 去重键创建独立输入卡；已绑定卡片时复用。避免摘要状态回调覆盖输入表单，保持不同事项草案来源唯一。此前“替换摘要原消息”方案已撤销。真实发送仍未执行。

### 重复快捷操作恢复专项
已绑定输入卡的重复点击仅返回已有结果，不重新 patch 旧快照，避免与用户提交后的生成/确认流程争抢卡片。生成中、已推进、已执行或过期草案拒绝重新打开；未完成卡片绑定的重试仍使用同一 action ID 与飞书 UUID。

### 聊天独立任务确认卡切片
创建任务快捷操作先生成本人可编辑草案，完整展示标题、截止时间、执行方式和参与人。确认回调携带 action ID 与版本；严格验证表单、身份、原卡片及租约后才调现有独立任务执行器。过期、重复、旧版本与失败恢复沿用持久状态边界。真实任务创建单独确认，开发验证不调用外部写入。

任务确认恢复修正：执行器 schedule 第三参数是 callbackToken，必须传验证回调 token 而非 message ID；已持久化 taskGuid 的独立任务重试跳过外部创建，仅恢复剩余结果步骤。

任务结果呈现与重试：仅任务产物成功时不显示客户/跟进已写入；原通用 retry 对独立任务必须再次检查 task:assign，权限撤销后不得通过旧失败卡执行。

独立任务编辑修订：executionTarget.taskGuid 指向原任务，operationKind=update 必须调用 updateTask；缺少更新能力时失败，禁止退化为 createTask。恢复时已持久 taskAction=updated 跳过更新。

任务编辑入口：成功结果提供编辑任务按钮；task:assign 在 edit/cancel/retry 分流前校验。编辑沿用原卡片修订关联，确认后执行器更新原 taskGuid。

### Web 任务执行结果查询切片
新增本人任务草案只读状态查询，返回等待确认、执行中、成功或失败及原任务链接。服务端检查 task:read、本人归属与 task 类型；客户端不得通过确认接口轮询，避免读操作触发重试。后续工作台保存 action ID 并短轮询，失败显式重试原 action。
# 2026-10-19 准备包编辑与事实分离

话术编辑独立于生成报告存储，仅允许已有渠道的主题/正文；保存必须比较结果 revision，且与元数据审计原子提交。权限按当前可见客户重新核验，不能因持有结果 ID 获得编辑权。不新增发送、Base 或任务副作用。Web 接入依赖项目规定的 forms-skill，当前未找到，后端继续推进。

# 2026-10-19 准备结果通知去重身份

通知发送键绑定持久结果 ID，避免未来重试因新触发消息而改变身份。无效或非 HTTP(S) 的工作台配置降级显示结果编号，不能让已保存结果因链接构造失败而丢失通知路径。此决定只修正通知构造边界；持久投递账本、冻结首次内容、超时 unknown 及权限重验仍须独立实现验收，不宣称外部发送恰好一次。

# 2026-10-19 准备通知独立投递账本

采用结果保存时原子创建的独立 outbox，而非复用主动提醒的收件成员/提醒类型账本。投递仅原始聊天，首次领取冻结内容；发送异常及过期领取一律 unknown，避免把不确定成功误当作可安全重试。旧结果无聊天归属，不自动补发。恢复入口必须重新校验本人及当前客户权限。

# 2026-10-19 准备投递状态只读边界

决定：状态接口先复用结果当前权限核验，仅返回 status；历史无账本返回 not_recorded。查询不清理过期 dispatching、不领取发送、不暴露投递内部字段。原因：查看状态不应产生恢复或发送副作用，历史缺少数据也不能推断成功/失败。人工核查和恢复单独设计，unknown 禁止直接重置。

# 2026-10-20 Playbook 版本草稿

已接受候选允许审核人主动编写独立版本草稿。候选行事务锁保护首次竞争及连续版本，requestId 按规范化内容和作者幂等重放；来源在服务端冻结。没有正式发布或 RAG 接入，自动观测继续不保存原始问答正文。见 SDD 51。

# 2026-10-19 准备投递人工确认

unknown 仅可由当前有权查看结果的本人，凭人工核验的飞书消息 ID、发送时间与说明确认成 sent；采用 reconciliationVersion 整数 CAS，并与独立审计原子提交。只读状态公开该版本用于并发保护。该切片不支持确认未发送或重发授权，unknown 不能 claim；系统不核验消息 ID 真伪，也不发送外部消息。
